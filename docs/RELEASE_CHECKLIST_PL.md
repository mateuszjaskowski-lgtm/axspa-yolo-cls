# Publikacja poprawionej wersji

Zmiany przygotowano względem commita 71eb2ec8eee8ed1bf0982bc0bef4e23669934d26. Zmiany są przeznaczone do przeglądu w pull requeście przed nowym wydaniem.

1. Wprowadź zmiany z tej gałęzi po sprawdzeniu różnic.
2. Potwierdź deklaracje autorów oraz dostępność kodu/danych. Nie wgrywaj danych indywidualnych bez właściwych uprawnień.
3. Uruchom analizę macierzy i testy oraz porównaj wyniki z artykułem.
4. Ustaw faktyczny numer wydania (np. 1.1.0) i datę w CITATION.cff. Nie przedstawiaj artykułu jako opublikowanego.
5. Utwórz nowe wydanie GitHub z nowym tagiem. Nie przesuwaj tagu v1.0.0.
6. Sprawdź połączenie GitHub–Zenodo i pojawienie się nowej wersji. DOI 10.5281/zenodo.22850852 dotyczy v1.0.0; DOI zbiorczy to 10.5281/zenodo.22850851.
7. Skopiuj rzeczywisty DOI nowej wersji do artykułu. Nie zgaduj jego numeru.
8. Sprawdź, że archiwum zawiera właściwy commit i pliki.

Nie odtwarzaj nieznanych wersji środowiska z pamięci. Nowy trening jest nowym eksperymentem, a nie dowodem pochodzenia wcześniejszych wyników.
